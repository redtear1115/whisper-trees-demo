# 03 打卡：掃樹牌 QR Code + GPS

## 為什麼這樣做

- 公園處樹牌上**已經有 QR Code**，不用新增設施。
- 只靠 QR Code，翻拍就能打卡；只靠 GPS，不知道是哪一棵樹。**QR 證明是哪一棵，GPS 證明人在現場**，兩者合起來才算打卡。
- 不做 NFC：目前沒有 NFC 樹牌，也沒有驗證過。

## 樹牌 QR Code 格式（已確認）

```
http://trees.gov.taipei/show/?treeid=SL0560111023
```

以實拍樹牌解碼確認，照片為 `material/samples/tree-tag-SL0560111023.jpg`。

**一定要在我們的網頁裡掃**。用手機內建相機掃會開到公園處的頁面，不會進到我們的網站。

## 流程

1. 按「掃樹牌」→ 要求相機權限 → 開後鏡頭掃描（不用按快門）。
2. 解出字串 → 取 `treeid`：
   - 先試網址參數 `treeid`。
   - 不是網址時，在字串裡找 `[A-Z]{2}\d{10}(-\d{3})?`。
   - 都找不到 → 「這好像不是樹牌，再試一次」。
3. 依 `treeid` 前 2 碼載入查詢表（[01](01-data-pipeline.md)）→ 找不到 → 「資料裡還沒有這棵樹」（資料是 2026-10-16 下載的版本，新植的樹可能還沒有）。
4. 同時要求定位，取得 `latitude`、`longitude`、`accuracy`。
5. 算出和樹的距離 `d`，判斷：

| 結果 | 條件 | 畫面 |
|---|---|---|
| 打卡成功 | `d ≤ 30 m + min(accuracy, 30 m)` | 回到地圖、這棵樹的拉近畫面，跳獎勵卡（見下「打卡成功之後」） |
| 遠觀模式 | 樹的 `RegionRemark` 是 `安全島`，且 `d ≤ 80 m` | 同上，獎勵卡寫「遠遠陪著它」；不算近距離打卡（安全優先，不必走到安全島上） |
| 太遠 | 其他 | 「你離這棵樹約 N 公尺，走近一點再掃一次」，仍可以看樹的資料 |
| 無法定位 | 使用者拒絕或逾時 10 秒 | 「沒有位置就無法打卡」，仍可以看樹的資料 |

**感應半徑**只有一個定義：`checkinRadius(accuracy) = nearMeters + min(accuracy, maxAccuracyBonus)`（`src/lib/geo.ts`）。打卡判斷（`judgeCheckin`）與地圖「附近」模式的人物感應圈（[02](02-map.md)）都呼叫它，兩邊不會不一致。Demo 模式的模擬位置誤差是 `CHECKIN.demoAccuracy`（5 m）→ 半徑 35 m。地圖上圈內有樹只是提示，打卡仍要掃樹牌 QR Code。

門檻值集中放在設定檔，Demo 前依現場測試調整。

## Demo 模式（模擬 GPS）

現場會場不在 Demo 的樹旁邊，需要備案：

- 網址帶 `?demo=1` 時，定位改成**可以移動的模擬位置**，畫面角落顯示「Demo 模式：模擬定位」。
  - 預設站在示範樹 `DA0030211045` 的位置（`DEMO`），所以現場照舊：開 `?demo=1`、掃示範樹牌就成功。
  - 模擬位置存在這個瀏覽器分頁（sessionStorage，經 store 的 `getDemoPosition` / `setDemoPosition` / `useDemoPosition`；`exitDemoMode` 會清掉）。移動的方式見 [02 地圖](02-map.md)：拖曳人物，或點樹後的「走過去」。
  - **掃樹牌用模擬位置判斷**（`CHECKIN.demoAccuracy`，`judgeCheckin` 不變）：離樹太遠就是「太遠」，和真實使用一樣；走到樹旁（35 m 內）才成功；安全島樹的遠觀規則照舊，只是距離從模擬位置算。示範按鈕（「掃示範樹牌（Demo）」「掃這棵樹的樹牌（Demo）」）只是代掃，不再假裝站在樹旁。帶著要掃的樹（`hintTreeId`）進掃描頁時，示範按鈕一進頁面就用那個編號（`Scanner` 的 `hintId`），不等樹種、路名載入，所以人走到別棵樹旁時不會誤掃到預設示範樹。
- README 已註明這是模擬資料。
- **首選**：Demo 前找一棵會場（北平東路 30-1 號）附近的真實行道樹，拍下樹牌、印出來，現場掃。這樣 GPS 也是真的。

## 掃碼實作

- 用 zxing 系列函式庫（`@zxing/browser` 或 `html5-qrcode`）。iOS Safari 沒有 `BarcodeDetector`。
- 同一張樹牌照片，OpenCV 解不出來、zxing 可以，所以不要用其他解碼器。
- 也提供「從相簿選照片」，給不方便開相機的情況。
- **相機打不開時**：取景框的位置換成說明卡（`camera-help`，`data-problem`；`src/features/checkin/camera.ts` 純函式有單元測試、`Scanner.tsx`）。
  - 開相機前先問權限狀態（Permissions API 的 `camera`，不支援就跳過）：已經被拒絕就直接顯示說明；之後在設定裡改成允許，會自動重開。
  - 依錯誤分類：權限被拒（`denied`）、沒有後鏡頭（先改用任何一個鏡頭再試一次，還是不行才是 `notFound`）、被別的 App 佔用（`busy`）、不是 HTTPS（`insecure`）、瀏覽器不支援（`unsupported`）。
  - **全黑（`noFrames`）**：拿到相機串流 4 秒（`NO_FRAMES_MS`）還沒有畫面。有些手機開了相機卻一直不出畫面，這時不會有任何錯誤，所以要主動偵測。
  - 權限視窗跳出來 3 秒還沒按：取景框下方提醒「看到『要使用相機嗎？』請按『允許』」（`camera-waiting`）；12 秒還沒有相機也沒有錯誤，改成說明卡（`unknown`）。
  - 說明卡：標題說發生什麼，接著一步步怎麼打開（iPhone Safari：網址列「大小」→ 網站設定 → 相機；iPhone Chrome：設定 → Chrome → 相機；Android Chrome：網址列左邊的圖示 → 權限 → 相機，再不行到系統設定的 Chrome 權限），最後一定是「先拍下樹牌，再從相簿選照片」；可以重試的有「重新開相機」（`camera-retry`）。在 App 內建瀏覽器（LINE、IG…）裡一律先請他改用 Safari／Chrome。
- 相機與定位只能在 HTTPS（或 localhost）使用。

## 防作弊（P2，只寫進未來展望）

- 同一棵樹一天只算一次打卡。
- 異常速度（兩次打卡距離 ÷ 時間不合理）標記。
- GPS 可以偽造，Demo 不處理。

## 掃描頁的提示

從地圖拉近畫面點互動（[02](02-map.md)）或樹頁面的「掃樹牌」鈕進來，路由 state 帶 `hintTreeId`：掃描頁底部多一行「要打卡的是：樹種・路名。找到它樹幹上的樹牌，對準 QR Code。」（`data-testid="scan-hint"`）；Demo 模式的示範按鈕變成「掃這棵樹的樹牌（Demo）」，掃的是這棵樹（沒有提示時照舊掃示範樹）。只是提示：掃到別棵樹、手動輸入編號都照常判斷，打卡判斷（`judgeCheckin`）不變。

**掃描頁版面**：頂端列、取景框所在的空間（`scanner-stage`）、底部提示與按鈕由上到下排成一欄（flex），不是各自絕對定位；取景框在頂端列與底部提示之間剩下的空間裡置中，空間不夠就縮小（最大 min(64vw, 280px)），所以提示卡、樹牌說明、相機錯誤訊息再長也蓋不到取景框。實測（Demo，帶樹提示、相機被拒、訊息最長的情況）：360×640 取景框 137 px、390×844 250 px，都在頂端列下緣與底部提示上緣之間；沒有水平捲動。取景框只是視覺引導，解碼用整個畫面，縮小不影響掃描。

## 打卡成功之後

打卡成功或遠觀時，`ScanPage` 記下打卡、發光點與掉落後回到 `/`，路由 state 是 `FocusAfterScan { focusTreeId, reward: { kind, glow, drops }, openCard? }`。地圖飛到那棵樹、打開拉近畫面，樹冠上先跳一張**獎勵卡**（`CheckinReward`，`checkin-reward`）：「打卡成功」（遠觀是「遠遠陪著它」）、「收進 N 道光點」（今天這棵樹拿過了就說已經收過），有掉落（稀有配件、樹上住戶，`DropCards`）一起亮出來。沒有掉落時 2.6 秒自己收起（`REWARD_AUTO_MS`），有掉落（有連結）就等按「好」；慶祝視窗（第一道光、徽章）開著時不倒數，等它關掉。收起後：從拉近畫面點互動來掃的（`/scan` 的 state 帶 `openCard`），**而且掃到的就是那一棵**，自動打開剛剛點的那張卡（摸摸樹、回報、留言在樹洞）；從底部導覽直接掃的，只停在拉近畫面，讓玩家自己選。路由 state 用過就清掉，重新整理不會再跳。**打卡本身不主動問心情**（做完摸摸樹、回報、樹洞時才問；樹的頁面有縮成一行的心情列，想補選可以展開）。太遠、無法定位不算打卡，照舊到樹的頁面看原因。樹的頁面只從拉近畫面的「樹的資料 › 打開這棵樹的頁面」或其他分頁進去。
