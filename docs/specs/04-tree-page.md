# 04 樹的頁面與樹洞

## 目的

打卡後的主畫面，也是曦語和一般查樹工具不同的地方：停下來、對樹說一句話、知道自己不孤單，但沒有社交壓力。

## 路由

`/tree/:treeId`。從打卡進來帶打卡狀態（成功 / 遠觀 / 只瀏覽）；從地圖點進來是「只瀏覽」，不能留樹洞。

**從地圖的行動圈進來**（[02](02-map.md)「點樹的行動圈」，2026-10-19）：點樹後樹旁有四個圈（Demo 五個），其中三個進這一頁（「怎麼走」「走過去」不換頁）：「樹的資料」→ `/tree/:id`；「樹洞」→ `/tree/:id#whisper`；「樹況回報」→ `/tree/:id#report`。頁面上的 `id="whisper"`（樹洞區，打卡後是輸入框，沒打卡是「掃樹牌」卡片）與 `id="report"`（樹況回報區）是錨點，樹資料載入後捲到那裡（減少動態時不用平滑捲動）。這幾條路只是「導覽」，不改變規則：沒掃樹牌打卡就仍是「只瀏覽」，不能留樹洞、不能回報。人在感應圈內（行動圈帶 `nearTree` 狀態）而還沒打卡時，樹洞區文案改成「你已經在樹旁邊了。掃一下樹幹上的樹牌，就能對它說句話。」，「掃樹牌」鈕帶這棵樹的編號（`hintTreeId`），掃描頁會提示要打卡的樹。

## P0

### 樹籍資料（真實）

樹種、樹高、胸徑、路名或公園、調查日期、樹籍編號。資料來源標「臺北市公園處開放資料」。

### 樹洞（存在使用者自己的雲端資料）

- 只有「打卡成功」或「遠觀模式」才能留言。
- 一次一句話，最多 140 字。不做語音（P2）。
- 存在 Firestore 的 `users/{uid}/whispers`，以 `treeId` 區分；安全規則讓其他使用者讀不到。畫面文案：「其他人看不到。存在曦語的雲端，不公開。」
- 沒有設定 Firebase 時退回 localStorage。
- 沒有按讚、沒有留言、沒有分享按鈕。

### 微光共鳴（模擬資料）

- 顯示「這棵樹本週有 N 道微光陪伴」，不顯示任何文字內容。
- N = 以 `treeId` 為種子產生的固定數字（0–30），加上自己本週有沒有來過。
- 標「模擬」。

### 樹況回報（2026-10-19 由 P1 提升為 P0：遊戲端先做打卡與回報）

- 只有「打卡成功」或「遠觀模式」才能回報（證明人在現場）；只瀏覽時提示「到樹旁掃樹牌才能回報」。
- **兩類擇一**：
  - **修剪有問題**，細項可複選：修剪過度、遮蔭過多、枝葉擋路
  - **樹木生病**，細項可複選：病蟲害、枯枝或落枝、樹幹傾斜或受損
- 可以補一句說明（最多 140 字）、附照片。照片只在本機預覽，不上傳。
- 送出後進到政府端，依路段彙整（[06](06-gov-console.md)）；回報紀錄存在 store。
- 討論紀錄見 [discussion-2026-10-17](../discussion-2026-10-17.md)。

### 時空膠囊

- 再次在同一棵樹打卡時，顯示「上次你在這裡說了……」與日期。
- Demo 需要預先放一則示範，例如「一年前的今天」，存在 `src/mock/`。

## P1

- **夜間「樹木休息中」**：依台北的日落與日出時間（SunCalc）切換畫面。晚上仍可留樹洞，但不給日照加成，提示注意安全。
- **光點 +10**：打卡成功時的小動畫。只做視覺回饋，不做光點經濟。

## P2（未來展望）

## 驗收

- [ ] 從打卡進來能留樹洞，重新整理後仍在；從地圖點進來不能留。
- [x] 從行動圈的「樹洞」進來，網址是 `#whisper`、頁面有 `#whisper` 區塊（沒打卡時是「掃樹牌」卡片，且帶 `hintTreeId`）；「樹況回報」同理 `#report`。頁面比一個螢幕短時捲不動，區塊本來就在畫面內（2026-10-19 Playwright 360 px）。
- [ ] 換一棵樹，樹洞內容不會互相出現。
- [ ] 另一個帳號讀不到（規則測試）。
- [ ] 微光人數同一棵樹每次打開都一樣（固定種子）。
- [ ] 打卡後能送出回報（兩類擇一），政府端依路段看得到；只瀏覽時不能回報。
- [ ] 樹洞輸入框的文字大小至少 16 px（避免 iOS 自動放大），銀髮族看得清楚。
