# 04 樹的頁面與樹洞

## 目的

打卡後的主畫面，也是曦語和一般查樹工具不同的地方：停下來、對樹說一句話、知道自己不孤單，但沒有社交壓力。

## 路由

`/tree/:treeId`。從打卡進來帶打卡狀態（成功 / 遠觀 / 只瀏覽）；從地圖點進來是「只瀏覽」，不能留樹洞。

**從地圖的行動圈進來**（[02](02-map.md)「點樹的行動圈」，2026-10-19）：點樹後樹旁有四個圈（Demo 五個），其中三個進這一頁（「怎麼走」「走過去」不換頁）：「樹的資料」→ `/tree/:id`；「樹洞」→ `/tree/:id#whisper`；「樹況回報」→ `/tree/:id#report`。頁面上的 `id="whisper"`（樹洞區，打卡後是輸入框，沒打卡是「掃樹牌」卡片）與 `id="report"`（樹況回報區）是錨點，樹資料載入後捲到那裡（減少動態時不用平滑捲動）。**第六輪（2026-10-20）：樹況回報搬進頁尾「關於這棵樹」那一摺裡**（見「樹況回報」），所以 `#report` 會先把那一摺打開、把回報表單展開（打卡過的樹；沒打卡的樹看到「去掃樹牌」），再捲過去；錨點的上緣留 52 px，不會被 Demo 細條蓋住。這幾條路只是「導覽」，不改變規則：沒掃樹牌打卡就仍是「只瀏覽」，不能留樹洞、不能回報。人在感應圈內（行動圈帶 `nearTree` 狀態）而還沒打卡時，樹洞區文案改成「你已經在樹旁邊了。掃一下樹幹上的樹牌，就能對它說句話。」，「掃樹牌」鈕帶這棵樹的編號（`hintTreeId`），掃描頁會提示要打卡的樹。

## P0

### 樹籍資料（真實）

樹種、樹高、胸徑、路名或公園、調查日期、樹籍編號。資料來源標「臺北市公園處開放資料」。

**受保護樹木標籤（2026-10-20）**：這棵樹在受保護樹木名冊裡（`public/data/protected-trees.json`，比對方式見 [08 §1](08-extensions.md)）時，**頁首樹名旁**有一個紅色手蓋印章樣式的「受保護樹木」按鈕（`protected-tag`，`<button>`、點擊範圍 44 px 高、`aria-expanded`／`aria-controls`；2026-10-20 第四輪批評 4：原本是主圖下方的綠色小標籤，埋在卡片下面）。點開頁首下方出現一小塊說明（`protected-note`）：「這是臺北市「受保護樹木」名冊裡的老樹，在它旁邊打卡，基礎光點是 20（GM 可調，讀 `gameConfig().protectedBase`）。」與出處「臺北市政府文化局「臺北市受保護樹木」開放資料，依位置與樹種比對到這棵樹；樹籍名冊比對，非官方認定。」再點一次收起。「關於這棵樹」裡原本那一行名冊出處因為重複而拿掉。名冊還沒讀到或讀不到就不顯示。

### 樹種照片（2026-10-20）

- 頁面頂部原本是佔位插畫 `tree-hero`；這個樹種（台北最常見的 40 種）有照片時，改成 `PhotoCarousel`（`src/features/species/PhotoCarousel.tsx`），沒有照片或照片索引讀不到就退回佔位插畫。
- **每棵樹固定一張**（2026-10-20 決定）：從這個樹種的照片裡，用樹籍編號的數字（含 `-001` 這類後綴）對張數取餘數挑一張（`photoIndexForTree`），同一棵樹每次都是同一張、相鄰的樹多半不同；只有一張所以沒有換頁按鈕與圓點。輪播只留在圖鑑的樹種詳情（[08 §3](08-extensions.md)）。
- 照片是**這個樹種**的照片，不是這一棵樹；照片下方固定寫「這個樹種的照片，不是這一棵樹。」。
- 來源只有 iNaturalist，**只收 CC0 與 CC BY**（不收 NC、SA、ND、保留所有權利），每種 4～6 張，每位攝影者一張。資料與規則見 [README](../../README.md)「真實開放資料」，檔案在 `public/data/species-photos/`（`index.json` 由 `src/lib/speciesPhotos.ts` 讀一次並快取）。
- 輪播（圖鑑詳情用；樹的頁面只放一張，同一個元件）：CSS scroll-snap 可左右滑，有上一張／下一張按鈕（`aria-label`）與圓點；**不自動換頁**；圖片 `alt`＝「<樹種>，攝影：<攝影者>」，第一張以外 `loading="lazy"`；減少動態時按鈕換頁不用平滑捲動。
- 每張照片下方標示：「© 攝影者, CC BY」或「CC0 攝影者」、授權條款連結、iNaturalist 原始觀察連結。打卡條（`CheckinStrip`）在有照片時排在輪播下方，不蓋住署名。署名那行獨佔一列，「授權條款」「iNaturalist 原照片」兩個連結排在下一列，字還是小字，但每個連結是 44 px 高的點擊範圍（第四輪 Y）。

### 樹洞（存在使用者自己的雲端資料）

- 只有「打卡成功」或「遠觀模式」才能留言。
- 一次一句話，最多 140 字。不做語音（P2）。
- 存在 Firestore 的 `users/{uid}/whispers`，以 `treeId` 區分；安全規則讓其他使用者讀不到。畫面文案：「其他人看不到。存在曦語的雲端，不公開。」
- 沒有設定 Firebase 時退回 localStorage。
- 沒有按讚、沒有留言、沒有分享按鈕。

### 微光共鳴（模擬資料）

- 顯示「這棵樹本週有 N 道微光陪伴」，不顯示任何文字內容。「？」說明鈕（第六輪改成真正的 44×44 `<button>`，圈本身 30 px；原本是 32 px 的 `<summary>` 加偽元素擴大點擊範圍，而且會折到下一行）和句子在**同一行**，句子太長可以折行（`text-wrap: balance`）；說明展開在下面整列，`aria-expanded`／`aria-controls`。微光圖示是線條圖示（`IconGlow`），不再是虛線佔位框（第六輪）。時空膠囊卡的信封（`IconCapsule`）同理。
- N = 以 `treeId` 為種子產生的固定數字（0–30），加上自己本週有沒有來過。
- 標「模擬」。

### 樹況回報（2026-10-19 由 P1 提升為 P0：遊戲端先做打卡與回報）

- **位置（第六輪，2026-10-20，設計批評 6）**：樹況回報不再是頁面最後的一張行政卡片，改收進最下面的「關於這棵樹」那一摺（`<details id="about">`，摘要寫「樹種、樹高、樹籍編號、樹況回報」），樹資料、資料來源之後是 `<div id="report">`。這樣頁面的情緒終點是樹洞與時空膠囊。`#report`（地圖行動圈、掃描頁、各處連結）一律先打開那一摺，打卡過的樹並把表單直接展開（`ReportBox` 的 `openForm`）。五個類別、送出、光點都不變。
- 只有「打卡成功」或「遠觀模式」才能回報（證明人在現場）；只瀏覽時提示「到樹旁掃樹牌才能回報」，並給一顆次要按鈕「去掃樹牌」（`report-scan`，≥ 44 px 高；第四輪批評 4 起不是綠色主要按鈕，因為同一頁樹洞區沒打卡時已有一顆主要的「掃樹牌」，一頁同時只留一顆綠色主要按鈕）→ `/scan`，帶 `state: { hintTreeId: tree.id }`（和樹洞區沒打卡時的「掃樹牌」同一個介面；2026-10-20 第四輪 Y，原本只有文字，從地圖「樹況回報」圈進來是死路）。
- **五類一鍵選**（2026-10-20 依團隊簡報 v17 第 22 頁；取代原本的「兩類加細項」，不再選細項）。id 與畫面文字：

  | # | id | 畫面文字 |
  |---|---|---|
  | 1 | `pruning` | 樹木修剪問題 |
  | 2 | `pest` | 病蟲害 |
  | 3 | `shade` | 遮蔭太多，或修剪過度 |
  | 4 | `sprout` | 新長枝芽擋路 |
  | 5 | `other` | 其他 |

- 選好類別就能送出。可以補一句說明（最多 140 字，輸入框字級 16 px，只有承辦人看得到，提示勿填個資）、附照片（`<input type="file" accept="image/*" capture="environment">`，手機直接開相機）。**照片只在這支手機上預覽，不上傳、不存進 Firestore**，畫面明講；雲端只存一個「有附照片」的布林值 `hasPhoto`，承辦人只知道有附，看不到照片。可以移除或換一張。
- 送出得 **+15 光點**（GM 可調，規則見 [08 §1](08-extensions.md)）；簡報另有「社區複驗通過再 +5」，**不做**（沒有複驗流程，記在 08 §1）。
- 送出後進到政府端，依路段彙整（[06](06-gov-console.md)），也變成發包商的養護工單；回報紀錄存在 store。
- **舊資料相容（2026-10-20）**：舊版的 `pruning`／`sick` 加細項照樣讀得出來，讀取時（`normalizeReportKind`，`src/store/types.ts`）換成新的五類：`pruning` 加「修剪過度」或「遮蔭過多」→ `shade`；`pruning` 加「枝葉擋路」→ `sprout`；`pruning` 沒細項 → `pruning`；`sick` 加「病蟲害」→ `pest`；`sick` 其他細項、不認得的 → `other`。已存的文件不改寫；舊細項（`details`）仍顯示在政府端與廠商端的說明裡。本機的舊回報搬到雲端時也照這個對照。
- `firestore.rules` 的回報驗證只接受**新增**這五個 id（`sick` 不能再新增，已存的舊文件仍可讀）；`details` 欄位仍存在，只為搬舊資料，新回報是空陣列。
- 討論紀錄見 [discussion-2026-10-17](../discussion-2026-10-17.md)。

## P1

    | `unsure` | 😶 | 說不上來 | 森林安靜地陪著你，不追問。 | 淡淡微光，不強求 |

    回應的寫法（第五輪）：**發生在現在**（不是簡報原本「出現可以坐下的樹根」這種之後才會有的事）、**第二人稱**、**不評價**（不說「你不要難過」）、**一句話**。動畫與音效不做，只有文字；**只有焦慮**那一句是邀請一次呼吸，旁邊有一個純 CSS 的小圓點（約 4 秒脹大、4 秒縮小；`prefers-reduced-motion: reduce` 時不動，只是一個靜止的圓點，`aria-hidden`）。生氣的回應是風和「我聽著」，沒有呼吸圓點。
  - **什麼時候問**（`shouldAskMood(now, lastAskedAt, intervalHours)`）：只在**剛掃樹牌打卡成功（含遠觀）進到樹的頁面**時問；普通造訪（從地圖點進來、重新整理後沒有新打卡）不問。**8 小時內最多問一次**：沒問過就問；距離上次詢問不到 8 小時就不問，剛好滿 8 小時就問。間隔是 GM 可調的 `moodIntervalHours`（預設 8，0 = 每次打卡都問，見 [08 §6](08-extensions.md)）。掃描頁（`ScanPage`）在記下打卡後算出 `askMood` 放進路由 state，樹的頁面還會再算一次；雲端模式使用者文件還沒載入就不問（看不到上次詢問的時間）。上次詢問時間在未來（時鐘調過）當作沒問過。**詢問時間在那一列顯示出來的那一刻就記下**（`noteMoodAsked`；不選也算問過，間隔內不再問）；記下後 `shouldAskMoodNow` 就變 false，所以樹的頁面用 state 記住「這一頁問過了」，這一列才不會一點就消失。重新整理後不再問；選過的話樹洞卡上只剩那一句回應。
  - **介面**：樹洞卡的標題、隱私說明（「只有你看得到…」）下面、輸入框**上面**是一列「**現在的心情？**（可以不選）」，下面是七個小按鈕（emoji 加名稱，折行排列；每個 ≥ 44 px 高；360 與 390 寬都是兩排，沒有水平捲動）。**不是原生 radio，是 `aria-pressed` 的按鈕**：用 Tab 逐個移動不會一路存下去。**點了就存**（`answerMood`：同時記下最新心情與詢問時間），再點別的就換；再點同一個就取消（`clearMood`，存 `current: null`）。選中的是**實心深綠底、白字、右上角一個勾**（不只靠邊框；勾在角上，不增加按鈕寬度，所以選了不會讓整列重新折行）。**沒有「就這個」「略過」**；選了之後下面只出現**一句**森林的回應（手寫字、綠色、`aria-live="polite"`，`data-testid="mood-response"`）。自然的下一步是在同一張卡寫樹洞（輸入框提示字維持「對這棵樹說一句話」，卡上已說明只有你看得到）。已經說過話、卡片換成「樹收到了」時，這一列移到卡片最下面（虛線隔開），**第六輪起縮成一行「心情：疲憊・改」**（`MoodCollapsed`，沒選過是「心情：沒選・選一個」；「改」是 ≥ 44 px 的按鈕，點了再展開七個按鈕，選了或取消就縮回一行；縮成一行時不顯示森林的回應句）。**七個心情按鈕的 emoji 一律放在同樣大的圓形淺黃底上**（24 px 圓，選中時圓底變白；「我的」的選擇器是 40 px 圓），系統 emoji 的顏色深淺不一，圓底讓它們看起來是一組；360 與 390 寬仍是兩排。
  - **遠觀**：遠觀打卡也有樹洞卡（只有打卡成功或遠觀才能留言），所以同一列在同一張卡上、規則完全相同；沒有打卡的瀏覽（卡片是「掃樹牌」邀請）不問。
  - **和其他東西共存**：打卡的小驚喜卡（`DropCards`）在標題圖下方、樹洞卡上面；第五輪把它縮成緊湊的小列（44 px 圖示、一句話、一行小字加連結，手機實測一張約 105 px，原本約 140 px）。**受保護樹木打卡後（驚喜卡加心情）樹洞卡在約 680 px 處開始（390×844 實測 682，目標 1,270 px 以內）**。**第一道光的慶祝視窗**（`OnboardingEffects` 的 `CelebrationDialog`；「回家的路」「城市的新朋友」同理）開著、或剛拿到第一道光而視窗馬上要跳出來時，心情那一列**不出現**、也還不記詢問時間，等視窗按「好」關掉才出現（`useCelebrationBlocking`，`src/features/onboarding/celebrationGate.ts`）。引導停在第 3 步時，第一道光的慶祝在地圖頁的引導抽屜裡、不在樹的頁面，所以不擋。
  - **回應是由資料推出來的**：有心情、在這棵樹有 30 分鐘內的打卡、且心情是在那次打卡之後選的，才顯示那一句（沒有那一列時，例如重新整理後，只顯示那一句、不能在這裡換）；之後再打卡（沒有再問）或心情清除就不顯示。
  - **換與清除也可以在「我的」**（[08 §11](08-extensions.md)）：`/me` 頂部 hero 動物、區的下面有一列「現在的心情：焦慮・剛剛」（**只有名稱，不帶 emoji**：臉部留白原則是 emoji 只在選擇的按鈕上，第五輪統一；展開的選擇器仍有 emoji）與「換心情」，沒選過是一行安靜的「還沒選心情。想的時候再選，沒有也沒關係。」與「選心情」。換心情不算一次詢問，不動「上次詢問時間」。
  - **存放**：只存最新一次的選擇與上次詢問的時間，不留歷史。`ext.mood = { current?: { id, at } | null, askedAt?: number }`（`current` 清除時寫 `null`，因為雲端是逐欄合併、欄位寫 `undefined` 清不掉）；雲端是 `users/{uid}` 的 `mood` map 欄位（擁有者本來就能寫自己文件的任何欄位，`firestore.rules` 沒有改）。寫入前先 `whenUserReady()`（和打卡的掉落一樣，太早寫會蓋掉雲端的資料；等不到逾時仍寫，因為是逐欄合併）。經過 store（`setExt('mood', …)`），元件不碰 Firestore 或 localStorage。**心情是使用者自己的資料**：不給別人看、不進政府端、不進 GM 統計、不進任何 API；存的是真實使用者輸入，不是模擬資料。本機搬到雲端（`migrate.ts`）目前只合併光點與造型，不搬 `onboarding`，也不搬心情（心情只是「現在」的一個狀態，換了裝置重選一次就好）。
