# 04 樹的頁面與樹洞

## 目的

打卡後的主畫面，也是曦語和一般查樹工具不同的地方：停下來、對樹說一句話、知道自己不孤單，但沒有社交壓力。

## 路由

`/tree/:treeId`。從打卡進來帶打卡狀態（成功 / 遠觀 / 只瀏覽）；從地圖點進來是「只瀏覽」，不能留樹洞。

**從地圖的行動圈進來**（[02](02-map.md)「點樹的行動圈」，2026-10-19）：點樹後樹旁有四個圈（Demo 五個），其中三個進這一頁（「怎麼走」「走過去」不換頁）：「樹的資料」→ `/tree/:id`；「樹洞」→ `/tree/:id#whisper`；「樹況回報」→ `/tree/:id#report`。頁面上的 `id="whisper"`（樹洞區，打卡後是輸入框，沒打卡是「掃樹牌」卡片）與 `id="report"`（樹況回報區）是錨點，樹資料載入後捲到那裡（減少動態時不用平滑捲動）。這幾條路只是「導覽」，不改變規則：沒掃樹牌打卡就仍是「只瀏覽」，不能留樹洞、不能回報。人在感應圈內（行動圈帶 `nearTree` 狀態）而還沒打卡時，樹洞區文案改成「你已經在樹旁邊了。掃一下樹幹上的樹牌，就能對它說句話。」，「掃樹牌」鈕帶這棵樹的編號（`hintTreeId`），掃描頁會提示要打卡的樹。

## P0

### 樹籍資料（真實）

樹種、樹高、胸徑、路名或公園、調查日期、樹籍編號。資料來源標「臺北市公園處開放資料」。

### 樹種照片（2026-10-20）

- 頁面頂部原本是佔位插畫 `tree-hero`；這個樹種（台北最常見的 40 種）有照片時，改成 `PhotoCarousel`（`src/features/species/PhotoCarousel.tsx`），沒有照片或照片索引讀不到就退回佔位插畫。
- **每棵樹固定一張**（2026-10-20 決定）：從這個樹種的照片裡，用樹籍編號的數字（含 `-001` 這類後綴）對張數取餘數挑一張（`photoIndexForTree`），同一棵樹每次都是同一張、相鄰的樹多半不同；只有一張所以沒有換頁按鈕與圓點。輪播只留在圖鑑的樹種詳情（[08 §3](08-extensions.md)）。
- 照片是**這個樹種**的照片，不是這一棵樹；照片下方固定寫「這個樹種的照片，不是這一棵樹。」。
- 來源只有 iNaturalist，**只收 CC0 與 CC BY**（不收 NC、SA、ND、保留所有權利），每種 4～6 張，每位攝影者一張。資料與規則見 [README](../../README.md)「真實開放資料」，檔案在 `public/data/species-photos/`（`index.json` 由 `src/lib/speciesPhotos.ts` 讀一次並快取）。
- 輪播（圖鑑詳情用；樹的頁面只放一張，同一個元件）：CSS scroll-snap 可左右滑，有上一張／下一張按鈕（`aria-label`）與圓點；**不自動換頁**；圖片 `alt`＝「<樹種>，攝影：<攝影者>」，第一張以外 `loading="lazy"`；減少動態時按鈕換頁不用平滑捲動。
- 每張照片下方標示：「© 攝影者, CC BY」或「CC0 攝影者」、授權條款連結、iNaturalist 原始觀察連結。打卡條（`CheckinStrip`）在有照片時排在輪播下方，不蓋住署名。

### 樹洞（存在使用者自己的雲端資料）

- 只有「打卡成功」或「遠觀模式」才能留言。
- 一次一句話，最多 140 字。不做語音（P2）。
- 存在 Firestore 的 `users/{uid}/whispers`，以 `treeId` 區分；安全規則讓其他使用者讀不到。畫面文案：「其他人看不到。存在曦語的雲端，不公開。」
- 沒有設定 Firebase 時退回 localStorage。
- 沒有按讚、沒有留言、沒有分享按鈕。

### 微光共鳴（模擬資料）

- 顯示「這棵樹本週有 N 道微光陪伴」，不顯示任何文字內容。
- N = 以 `treeId` 為種子產生的固定數字（0–30），加上自己本週有沒有來過。
- 標「模擬」。

### 樹況回報（2026-10-19 由 P1 提升為 P0：遊戲端先做打卡與回報）

- 只有「打卡成功」或「遠觀模式」才能回報（證明人在現場）；只瀏覽時提示「到樹旁掃樹牌才能回報」。
- **五類一鍵選**（2026-10-20 依團隊簡報 v17 第 22 頁；取代原本的「兩類加細項」，不再選細項）。id 與畫面文字：

  | # | id | 畫面文字 |
  |---|---|---|
  | 1 | `pruning` | 樹木修剪問題 |
  | 2 | `pest` | 病蟲害 |
  | 3 | `shade` | 遮蔭太多，或修剪過度 |
  | 4 | `sprout` | 新長枝芽擋路 |
  | 5 | `other` | 其他 |

- 選好類別就能送出。可以補一句說明（最多 140 字，輸入框字級 16 px，只有承辦人看得到，提示勿填個資）、附照片（`<input type="file" accept="image/*" capture="environment">`，手機直接開相機）。**照片只在這支手機上預覽，不上傳、不存進 Firestore**，畫面明講；雲端只存一個「有附照片」的布林值 `hasPhoto`，承辦人只知道有附，看不到照片。可以移除或換一張。
- 送出得 **+15 光點**（GM 可調，規則見 [08 §1](08-extensions.md)）；簡報另有「社區複驗通過再 +5」，**不做**（沒有複驗流程，記在 08 §1）。
- 送出後進到政府端，依路段彙整（[06](06-gov-console.md)），也變成發包商的養護工單；回報紀錄存在 store。
- **舊資料相容（2026-10-20）**：舊版的 `pruning`／`sick` 加細項照樣讀得出來，讀取時（`normalizeReportKind`，`src/store/types.ts`）換成新的五類：`pruning` 加「修剪過度」或「遮蔭過多」→ `shade`；`pruning` 加「枝葉擋路」→ `sprout`；`pruning` 沒細項 → `pruning`；`sick` 加「病蟲害」→ `pest`；`sick` 其他細項、不認得的 → `other`。已存的文件不改寫；舊細項（`details`）仍顯示在政府端與廠商端的說明裡。本機的舊回報搬到雲端時也照這個對照。
- `firestore.rules` 的回報驗證只接受**新增**這五個 id（`sick` 不能再新增，已存的舊文件仍可讀）；`details` 欄位仍存在，只為搬舊資料，新回報是空陣列。
- 討論紀錄見 [discussion-2026-10-17](../discussion-2026-10-17.md)。

### 時空膠囊

- 再次在同一棵樹打卡時，顯示「上次你在這裡說了……」與日期。
- Demo 需要預先放一則示範，例如「一年前的今天」，存在 `src/mock/`。

## P1

- **夜間「樹木休息中」**：依台北的日落與日出時間（SunCalc）切換畫面。晚上仍可留樹洞，但日照倍率是 ×1（沒有加成），提示注意安全。
- **光點 +N**：打卡成功時的小動畫。N 依 [08 §1](08-extensions.md) 的規則算（基礎、日照、寂寞樹…），流水帳寫明用了哪些規則。

## 驗收

- [ ] 樹的頁面每棵樹固定一張照片（依樹籍編號取餘數），沒有換頁按鈕；重新整理仍是同一張。
- [x] （圖鑑詳情的輪播；原本在樹的頁面驗過）有照片的樹種：樹的頁面頂部是輪播，每張都有署名、授權與原始觀察連結；下一張按鈕、手指滑動（CDP 觸控手勢）、圓點、上一張循環、鍵盤都有效；索引讀不到時退回佔位插畫（2026-10-20 Playwright 360 px，`/tree/DA0030211045?demo=1`，沒有水平捲動）。**沒有在實機（iOS Safari）驗過滑動手感。**
- [ ] 從打卡進來能留樹洞，重新整理後仍在；從地圖點進來不能留。
- [x] 從行動圈的「樹洞」進來，網址是 `#whisper`、頁面有 `#whisper` 區塊（沒打卡時是「掃樹牌」卡片，且帶 `hintTreeId`）；「樹況回報」同理 `#report`。頁面比一個螢幕短時捲不動，區塊本來就在畫面內（2026-10-19 Playwright 360 px）。
- [ ] 換一棵樹，樹洞內容不會互相出現。
- [ ] 另一個帳號讀不到（規則測試）。
- [ ] 微光人數同一棵樹每次打開都一樣（固定種子）。
- [ ] 打卡後能送出回報（五類一鍵選、不選細項），政府端依路段看得到；只瀏覽時不能回報。照片只預覽、不上傳（2026-10-20 Playwright 360 px：五個類別、照片預覽、輸入框 16 px、無水平捲動；實機拍照待測）。
- [x] 舊的 `pruning`／`sick` 回報仍能顯示（對照見上；單元測試 `reportKinds.test.ts`）。
- [ ] 樹洞輸入框的文字大小至少 16 px（避免 iOS 自動放大），銀髮族看得清楚。
